# messenger-inbox

Веб-чат для WhatsApp на базе [GREEN-API](https://green-api.com/). Пользователь
вводит данные своего инстанса и номер собеседника, после чего обменивается с
ним текстовыми сообщениями. Интерфейс повторяет WhatsApp Web.

Проект выполнен как тестовое задание: набор функций ограничен сценарием
«отправил сообщение — получил ответ».

## Возможности

- вход по `idInstance` и `apiTokenInstance` с проверкой, что инстанс
  авторизован;
- отправка и получение текстовых сообщений;
- статусы сообщений: отправляется, отправлено, доставлено, прочитано,
  не отправлено (с кнопкой «Повторить»);
- история переписки и сессия сохраняются в `localStorage` и переживают
  перезагрузку страницы;
- автоматическое переподключение при обрыве сети; опрос приостанавливается,
  пока вкладка скрыта.

## Быстрый старт

### Требования

- Node.js 20 или новее
- [pnpm](https://pnpm.io/)
- инстанс GREEN-API (см. ниже)

### Подготовка инстанса GREEN-API

1. Создайте инстанс в личном кабинете [green-api.com](https://green-api.com/).
2. Привяжите WhatsApp по QR-коду. Статус инстанса должен стать `authorized`,
   иначе экран входа не пропустит дальше.
3. В настройках инстанса включите входящие уведомления (`incomingWebhook`).
   Без этого ответы собеседника не придут: они попадают в очередь на стороне
   GREEN-API, а приложение только читает её.
4. Скопируйте `idInstance` и `apiTokenInstance` — их запрашивает форма входа.

### Установка и запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется на http://127.0.0.1:5173/.

## Конфигурация

Адрес API формируется автоматически:
`https://{первые 4 цифры idInstance}.api.green-api.com`. Если ваш инстанс
находится на другом адресе, задайте его в переменной окружения (шаблон —
[.env.example](.env.example)).

| Переменная          | Обязательна | Описание                                   |
| ------------------- | ----------- | ------------------------------------------ |
| `VITE_API_BASE_URL` | нет         | Базовый URL API вместо вычисляемого адреса |

## Архитектура

### Работа с API

Весь обмен с GREEN-API находится в `src/api`. Учётные данные подставляются в
URL в одном месте — `messengerApi.ts`, поэтому смена эндпоинтов затрагивает
один файл. `notifications.ts` преобразует вебхуки в сообщения приложения.

### Получение сообщений

Входящие сообщения читает цикл в `features/chat/pollLoop.ts`: он вызывает
`ReceiveNotification`, а после обработки каждого уведомления — обязательно
`DeleteNotification`, иначе API пришлёт то же уведомление снова. Ошибки
обрабатываются по трём сценариям:

| Ситуация                         | Поведение                                |
| -------------------------------- | ---------------------------------------- |
| Сбой сети или API                | повтор с экспоненциально растущей паузой |
| Ответ 401 или 403                | выход на экран входа с описанием причины |
| Уведомление не удалось разобрать | пропускается, но удаляется из очереди    |

### Состояние и хранение

- Переписка хранится по чатам (`threads` в `chatSlice.ts`), закрытый чат не
  теряет историю. Порядок сообщений в ленте соответствует порядку их
  поступления.
- Повторные уведомления отсекаются по `idMessage`. Эхо собственного сообщения,
  пришедшее через API раньше ответа на отправку, объединяется с ожидающим
  сообщением, а не добавляется как дубль.
- Сессия и переписка сохраняются в `localStorage` (ключ `messenger-inbox:v2`).
  Данные проверяются при чтении, испорченные записи отбрасываются; для каждого
  чата хранятся последние 500 сообщений.
- Приложение работает только в одной вкладке: вторая вкладка ждёт и
  подхватывает работу после закрытия первой.

## Деплой

Приложение — статические файлы без серверной части. Для Vercel достаточно
импортировать репозиторий: пресет Vite определяется автоматически, команда
сборки — `pnpm build`, каталог вывода — `dist`. Переменные окружения не нужны.

Учётные данные вводит пользователь, в сборку они не попадают.
